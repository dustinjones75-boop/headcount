# Solution Exploration

## Purpose
Explore materially different ways to solve a problem before implementation locks into the first plausible approach.

## Invoke when
Use when architecture, platform choice, integration pattern, or workflow design has multiple credible paths.

## Method
1. Define the problem and non-negotiable constraints.
2. Generate 2–4 genuinely different approaches, not cosmetic variants.
3. Compare complexity, cost, maintainability, reversibility, dependency risk, and time to value.
4. Identify the cheapest test that can eliminate a weak option.
5. Recommend one path and explain what would make another preferable.

## Tool behavior
Inspect the existing stack and connected systems before recommending replacement technology.

## Output
Return the options, tradeoffs, recommendation, and the first validation step.
